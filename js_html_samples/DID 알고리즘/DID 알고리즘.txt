**DID(Decentralized Identifier) 관련 알고리즘은 크게 ‘DID 생성 및 관리’, ‘검증(Verification)’, ‘합의(Consensus)’ 영역에서 정의되어 있으며, W3C DID 표준과 블록체인 기반 구현체들이 이를 뒷받침합니다. OTP 같은 단기 인증과 달리 DID는 공개키 암호화와 분산 네트워크 알고리즘을 기반으로 합니다.**

---

## 🔑 DID 관련 주요 알고리즘

### 1. DID 생성 알고리즘
- **DID 문법**: `did:<method>:<identifier>`  
  예: `did:example:123456789abcdefghi`
- **Identifier 생성**:  
  - 해시 함수(SHA-256 등)를 사용해 고유 식별자 생성  
  - 블록체인 트랜잭션 ID 또는 공개키 기반 생성
- **Method-specific Registry**: 각 DID 메서드별로 네트워크에 등록하는 알고리즘 존재 (예: `did:ethr`, `did:sov`)

### 2. DID Document 관리 알고리즘
- **문서 구조**: JSON-LD 기반, 공개키·서비스 엔드포인트 포함  
- **업데이트 알고리즘**: 블록체인 트랜잭션을 통해 DID Document를 갱신  
- **검증 키 회전(Key Rotation)**: 오래된 키를 폐기하고 새로운 키를 등록하는 알고리즘

### 3. 검증(Verification) 알고리즘
- **공개키 암호화 기반**: Ed25519, secp256k1 등 서명 알고리즘 사용  
- **Verifiable Credential(VC) 검증**:  
  - 발급자 DID → 서명 검증  
  - 소유자 DID → 제시(Presentation) 검증  
- **Zero-Knowledge Proof(ZKP)**: 개인정보를 노출하지 않고 검증하는 알고리즘

### 4. 합의(Consensus) 알고리즘
- **블록체인 기반 DID**: PoW, PoS, BFT 등 합의 알고리즘을 통해 DID Document의 무결성 보장  
- **P2P 멀티 패스 프로토콜 적용 가능성**: DID 데이터를 여러 경로로 분산 검증하여 신뢰성 강화

## 📌 DID 알고리즘과 OTP 비교
| 항목 | DID | OTP |
|------|-----|-----|
| **역할** | 영구적 신원 식별자 | 일회성 인증 코드 |
| **기술 기반** | 공개키 암호화, 블록체인 합의 | 시간 기반(TOTP), 카운터 기반(HOTP) |
| **보안성** | 장기적 신원 관리, 분산 검증 | 단기적 세션 보안 |
| **응용** | 분산 ID, VC/VP 인증 | 2FA, 로그인 보안 |

---

## ⚠️ 고려해야 할 점
- **DID는 표준화(W3C DID Core)**가 진행 중이며, 각 메서드별 구현 알고리즘이 다름.  
- **보안성은 공개키 암호화와 합의 알고리즘에 의존**하므로, 키 관리가 핵심.  
- **OTP는 DID와 직접 대응하지 않지만, DID 기반 인증 시스템에서 보완적 계층으로 활용 가능**.

---

👉 요약하면, DID 관련 알고리즘은 **식별자 생성(해시/공개키), 문서 관리(블록체인 등록·갱신), 검증(암호화·ZKP), 합의(분산 네트워크)**로 구성됩니다. OTP와는 성격이 다르지만, DID 인증 체계에 **추가 보안 계층**으로 결합할 수 있습니다.
